# Namco C139 — knowledge base

Serial controller ("Serial I/F Controller") of the Namco System 2, System 21, System 22 and Super System 22 boards.
System 23 uses a pin-compatible C422. The chip links the cabinets in a ring: each C139 transmits to the next one.
In Driver's Eyes and Ridge Racer Full Scale, it also links the boards of a single machine.

This file sums up how the chip works, as deduced from the games' code, and the emulation model that follows from it.
The detailed analyses are in `C139_docs/`: commented pseudo-code, addresses, variables, settings.
- `system2.md`: Final Lap 1/2/3, Four Trax, Suzuka 8 Hours 1/2, Dirt Fox, Kyuukai Douchuuki, Super World Stadium, plus how the other System 2 games use the chip.
- `system21.md`: Winning Run, Winning Run Suzuka GP, Winning Run '91, Driver's Eyes, Cyber Sled, Air Combat, Starblade, Solvalou.
- `s22_mode08.md`: Ridge Racer 2, Rave Racer, Ridge Racer, Ridge Racer Full Scale.
- `s22_mode09.md`: Ace Driver, Ace Driver Victory Lap, Cyber Commando, Armadillo Racing, Cyber Cycles.
- `super22.md`: Tokyo Wars, Alpine Racer 2, Alpine Racer, Alpine Surfer, Aqua Jet, Prop Cycle, Time Crisis, Air Combat 22, Dirt Dash.
- Tools: `dumpall.py` (dumps each game's regions through MAME), `c139scan.py` (finds and disassembles the accesses to the C139),
  `c139dis.py` (disassembles a range, putting the 68000/68020 regions back in big-endian order).

Method: program regions dumped by MAME (`mame.exe -autoboot_script`), then static analysis of the 54 parent games (capstone M68K),
then checks on two to four MAME instances linked over TCP (§ 6).

## 3. The chip, according to the games

### 3.1 RAM
- 0x2000 words of **9 bits**. Words 0x0000-0x0FFF = transmit area, 0x1000-0x1FFF = **receive ring**.
- Bit 8 marks the end of a frame (sync). The games set it on the last word of a frame, usually a checksum | 0x100,
  and look for it backwards from RXOFFSET to find the last frame received.
- Host memory map: System 2 RAM 0x480000 / registers 0x4A0000; System 21 0xB00000 / 0xB80000;
  System 22 0x20010000 / 0x20020000; Super 22 0x410000 / 0x420000.

### 3.2 Registers (Namco names from Cyber Cycles' COMMUNICATION screen)

| Reg | MAME | Namco | Behaviour |
|---|---|---|---|
| 0 | STATUS | **IRQ** | bit 0 error, bit 1 frame received, bit 2 transmitter free (**live**, 1 after reset; acedrive and victlap wait for it before their init). A write clears bits 0-1 where the data is 0 (`STATUS = 0`, `bclr #1`); bit 2 cannot be changed. |
| 1 | MODE | **MSK** | interrupt mask, 1 = masked: bit 1 receive, bit 2 transmitter free; bit 3 must be 1 for any IRQ (winrun writes 0 and never acknowledges). **When it raises an IRQ, the chip sets the matching bit**; the game clears it to re-arm. The "modes" 0x08, 0x09, 0x0C, 0x0D, 0x0F of the old notes are masks: 0x0D = 0x09 with the transmit IRQ masked, 0x0F = everything masked (init, menus). |
| 2 | CONTROL | **B-9** | forces bit 8 of the host's writes: 1 = to 0, 3 = to 1. ridgera2 and raverace write the frame with 1, then the checksum (last word) with 3; sws does the same. The other games leave it at 0 and write bit 8 themselves. |
| 3 | START | **S-M** | bit 0 = transmitter held while the game programs it (START 1; TXOFFSET; TXSIZE; START 0). Value written under MSK 0x0F: 3 (System 2, acedrive…), 0x11 (ridgera2), 0 (cybrcycc); meaning unknown (1/2 Mbit/s rate?). |
| 4 | RXSIZE | **R-C** | **decremented** for each word received; never stops the reception. Final Lap clears it and expects −0x14 (−0x16) in its IRQ; the loopback test loads it with n and waits for 0. |
| 5 | TXSIZE | **S-C** | number of words to transmit. Transmission starts when TXSIZE ≠ 0 and START bit 0 = 0; TXSIZE stays ≠ 0 during the transmission (the games test it as "busy") and **goes back to 0** at the end. |
| 6 | RXOFFSET | **R-AD** | next receive address: words go to `0x1000 | (RXOFFSET & 0xFFF)`, post-incremented without touching bit 12. |
| 7 | TXOFFSET | **S-AD** | **13-bit** word address, post-incremented, wrapping within its half of the RAM. The games rewrite it before each frame; 0x1000 + position is used to **relay** a frame directly from the receive ring. |

### 3.3 What the chip does not do
- **No relay, no filtering, no frame modification, no ring ID.** Every game relays frames itself.
  It increments a hop counter in the frame in RX RAM, fixes the checksum and transmits it again with TXOFFSET = 0x1000 + position.
  Each game recognises and drops its own frames when they come back (PCB number, slot, CPU NO.).
  The number of cabinets is deduced from the hops of its own frame when it comes back: "UP TO n", "LINK OK n", LINKCT.
- There is no "byte" unit for TXOFFSET: the `>> 1` of the old emulation (START = 3) is wrong.
- There is no search for the sync bit when transmitting (`find_sync_bit`) and no "+= 0x100" on TXOFFSET: these mechanisms only
  made up for the missing "transmitter free" IRQ.

### 3.4 Interrupts
- Frame received → STATUS bit 1 → IRQ if MSK bit 3 = 1 and MSK bit 1 = 0; the chip then sets MSK bit 1.
- Transmitter free (STATUS bit 2) and MSK bit 2 = 0 → IRQ; the chip sets MSK bit 2. This is how the games ask for an IRQ when they have
  frames queued (`MSK &= 0x0B` / `MSK = 9` at VBLANK) and empty the queue one frame per IRQ; they leave the bit at 1 (0x0D) when the queue is empty.
  Without this lock set by the chip, Cyber Commando, Armadillo Racing and Dirt Fox go into an IRQ storm or never transmit.
- **Only one frame per receive IRQ.** The handlers only parse the last frame before RXOFFSET. The next frame
  is only written once the game has cleared STATUS bit 1 and MSK bit 1: that is the last write of every handler,
  and Four Trax writes STATUS = 0 before acknowledging the interrupt controller.
- The IRQs are re-evaluated on every write to MSK.

### 3.5 Typical frames (details in the analyses)

| Family | Frame | Relay | Counting |
|---|---|---|---|
| Final Lap (S2) | 0x14 words (0x16 FL2/FL3): PCB number, data, hops, checksum \| 0x100 | TXOFFSET in the RX area, from VBLANK (up to 9 frames in a row) | hops of its own frame → "UP TO n" |
| FT / S8H / DF (S2) | 0x25 words (DF 0x20), type 0x41/0x66/0x82/0x42, 16 slots | queue driven by the transmitter-free IRQ | word 0x10 = N − 1 |
| Winning Run GP/'91, Cyber Sled (S21) | sender number, type 0x21/0x99, hops, data, checksum \| 0x100; 0x2A/0x24/0x5E words | same, on the slave CPU | "LINK OK n" |
| ridgera2 / raverace (S22) | 0x24 / 0x28 words, one byte per half-word, length, checksum (bit 8 through CONTROL = 3) | from the "transmitter free" IRQ; raverace adds the AI opponents (slots 8-15) | LINKCT if its own frame comes back within 16 / 8 VBLANKs |
| Family A: acedrive, victlap, cybrcomm, adillor (S22) | slot, magic byte 0x8D/0x9C/0x94/0xB0, hops, PCB number, data, checksum \| 0x100 | from the RX area | LINKCT = hops − 2 |
| cybrcycc (SS22) | 0x5A, node \| hops << 4, length in the sync word | copied to the TX area (0x800 + 0x200 × node) | renumbering by hop count |
| Tokyo Wars (SS22) | 0x46 words `[0x81+id][hops][0xA2][0x73+id][64 bytes][hops][0x100\|checksum]` | from the RX area, one frame per VBLANK | hops of its own frame |
| Alpine Racer 2 (SS22) | `[0xA5][n bytes][0x100\|(n+1)]`, TXSIZE = n + 2 | none (2 cabinets) | tag 0x173xxxx \| ID in the data |
| Driver's Eyes (S21) | the centre board sends 4 frames of 0x80 words (ending with 0xFFFF) on each request | the sides only receive | — |

## 4. The emulation model (`src/mame/namco/namco_c139.cpp`)
- Registers and RAM as in § 3. Transmission copies the words when it starts; the transmitter stays busy 5.5 µs per word
  (about 2 Mbit/s), then TXSIZE goes back to 0, the transmitter is free again and the IRQs are re-evaluated.
- Reception: one network frame per IRQ cycle, written into the RX ring, RXOFFSET advanced, RXSIZE decreased, STATUS bit 1.
- Transport: TCP, one incoming connection (`-comm_localhost/-comm_localport`) and one outgoing connection to the next cabinet
  (`-comm_remotehost/-comm_remoteport`). Each frame is prefixed with its length, with the 9-bit words on 2 bytes.
  A single instance with the default options (local port = remote port) connects to itself: its ring is looped back,
  like a cabinet with a test plug.
- Driver's Eyes: the three C139s are linked directly in the driver (`add_local_peer`); what one transmits reaches the two others.
  This replaces the old `sci_de_hack`, which opened fixed TCP ports.
- Super 22 (`namcos22.cpp`): a SCI request raised while the game has disabled that level in the system controller is remembered and
  delivered when the game enables it again. Alpine Racer 2 disables `$700002` while it transmits.
- Fixed along the way: a race between the emulation thread and the network thread could stall the TCP transmission for good
  (data left in the queue with no send in progress).

## 5. Points still unconfirmed
- Meaning of START = 3 / 0x11 / 0 under MSK 0x0F (rate?), of CONTROL = 2 and of bits 0 and 3 of MSK (only bit 3 = 1 is required for IRQs).
- A transmission stopping at the first word carrying bit 8 when MSK bit 0 = 1: FT (TXSIZE 0x2C for 0x25 words), DF (0x3F for 0x20)
  and Winning Run (0x3F for 0x2A) suggest it. The model sends the whole TXSIZE; the games tolerate it.
- Actual wiring of Driver's Eyes and Ridge Racer Full Scale (broadcast from the centre board to the sides).
- Actual line rate.

## 6. Test results (2026-11-03)
`c139.exe` contains the namcos2/21/21_c67/21_de/22 drivers with this model. The instances are linked by a local TCP ring
that uses the cabinets' addresses (127.0.0.4:15112 → 127.0.0.5:15113 → …). Each cabinet starts from its own NVRAM (§ 7).
Final regression run: the 15 games with 4 cabinets, then 6 games of different families with 2 cabinets, the second one started 12 s later.

What each fix solved:
- Removing the relay and the ring ID, plus the MSK lock set by the chip, made ridgera2 and raverace link, as well as Final Lap and the slot-based
  games (Four Trax, Suzuka, Dirt Fox) when each cabinet has its own number. The old emulation only linked raverace with two identical ring IDs,
  and acedrive, victlap or Winning Run only with different IDs, and only with 2 cabinets.
- Fixing the race in the network thread: without it, an instance's TCP transmission could stall for good (ridgera2 triggered it).
- Retrying a receive request left unanswered: Driver's Eyes at startup, Alpine Racer 2 while it transmits.

## 7. Link NVRAMs
The NVRAMs of cabinets 1 to 4 of each game are in the results folder (see the README that comes with them). Particular points:
- Final Lap 1/2/3: PCB number 0xFE01 to 0xFE04 (bytes 0x10-0x11), no checksum.
- Armadillo Racing: the settings record (0x200 bytes) is seen by the 68020 as 16-byte lines at `r×16` and `0x1000 + r×16`.
  The 16-bit sum of bytes 0-0x1FD is at 0x1FE (file 0x10FE-0x10FF). There is a backup copy (lines 0x10-0x1F).
- Winning Run GP / '91: bytes 8 (CAR TYPE) and 9 (CPU NO.), checksum of bytes 0-0xB at 0xC.
- Dirt Fox: CAR TYPE at byte 0x47, checksum at 0x41 (files generated by the menu).
- Alpine Racer 2: byte 0x32 = 0 (LEFT) / 1 (RIGHT), no checksum.
- Cyber Cycles: byte 0x26 = ID (0-3), accepted as is ("ID NUMBER 2, LINK ON 2").
