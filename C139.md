# Namco C139 — base de connaissances

Contrôleur série (« Serial I/F Controller ») des cartes Namco System 2, System 21, System 22 et Super System 22.
System 23 utilise un C422 compatible broche à broche. La puce relie les bornes en anneau (link) : chaque C139 émet vers le suivant.
Dans Driver's Eyes et Ridge Racer Full Scale, elle relie aussi les cartes d'une même machine.

Ce fichier résume le fonctionnement déduit du code des jeux et le modèle d'émulation qui en découle.
Les analyses détaillées sont dans `C139_docs/` : pseudo-code commenté, adresses, variables, réglages.
- `system2.md` : Final Lap 1/2/3, Four Trax, Suzuka 8 Hours 1/2, Dirt Fox, Kyuukai Douchuuki, Super World Stadium, plus le classement des autres jeux System 2.
- `system21.md` : Winning Run, Winning Run Suzuka GP, Winning Run '91, Driver's Eyes, Cyber Sled, Air Combat, Starblade, Solvalou.
- `s22_mode08.md` : Ridge Racer 2, Rave Racer, Ridge Racer, Ridge Racer Full Scale.
- `s22_mode09.md` : Ace Driver, Ace Driver Victory Lap, Cyber Commando, Armadillo Racing, Cyber Cycles.
- `super22.md` : Tokyo Wars, Alpine Racer 2, Alpine Racer, Alpine Surfer, Aqua Jet, Prop Cycle, Time Crisis, Air Combat 22, Dirt Dash.
- Outils : `dumpall.py` (vidage des régions de chaque jeu par MAME), `c139scan.py` (recherche et désassemblage des accès au C139),
  `c139dis.py` (désassemblage d'une plage, avec remise en ordre big-endian des régions 68000/68020).

Méthode : régions programme vidées par MAME (`mame.exe -autoboot_script`), puis analyse statique des 54 jeux parents (capstone M68K),
puis vérification sur deux à quatre instances de MAME reliées en TCP (§ 6).

## 3. La puce, d'après les jeux

### 3.1 RAM
- 0x2000 mots de **9 bits**. Mots 0x0000-0x0FFF = zone d'émission, 0x1000-0x1FFF = **anneau de réception**.
- Le bit 8 marque la fin de trame (synchro). Les jeux le posent sur le dernier mot d'une trame, en général une somme de contrôle | 0x100,
  et le cherchent en remontant depuis RXOFFSET pour retrouver la dernière trame reçue.
- Plan mémoire hôte : System 2 RAM 0x480000 / registres 0x4A0000 ; System 21 0xB00000 / 0xB80000 ;
  System 22 0x20010000 / 0x20020000 ; Super 22 0x410000 / 0x420000.

### 3.2 Registres (noms Namco de l'écran COMMUNICATION de Cyber Cycles)

| Reg | MAME | Namco | Comportement |
|---|---|---|---|
| 0 | STATUS | **IRQ** | bit 0 erreur, bit 1 trame reçue, bit 2 émetteur libre (**en direct**, à 1 après reset ; acedrive et victlap l'attendent avant l'init). Une écriture efface les bits 0-1 aux positions où la donnée vaut 0 (`STATUS = 0`, `bclr #1`) ; le bit 2 n'est pas modifiable. |
| 1 | MODE | **MSK** | masque d'interruptions, 1 = masqué : bit 1 réception, bit 2 émetteur libre ; bit 3 doit valoir 1 pour toute IRQ (winrun écrit 0 et n'acquitte jamais). **En levant une IRQ, la puce met à 1 le bit correspondant** ; le jeu le remet à 0 pour réarmer. Les « modes » 0x08, 0x09, 0x0C, 0x0D, 0x0F des anciennes notes sont des masques : 0x0D = 0x09 avec l'IRQ d'émission masquée, 0x0F = tout masqué (init, menus). |
| 2 | CONTROL | **B-9** | force le bit 8 des écritures de l'hôte : 1 = à 0, 3 = à 1. ridgera2 et raverace écrivent la trame avec 1, puis la somme (dernier mot) avec 3 ; sws pareil. Les autres jeux l'ont à 0 et écrivent le bit 8 eux-mêmes. |
| 3 | START | **S-M** | bit 0 = émetteur retenu pendant que le jeu le programme (START 1 ; TXOFFSET ; TXSIZE ; START 0). Valeur écrite sous MSK 0x0F : 3 (System 2, acedrive…), 0x11 (ridgera2), 0 (cybrcycc) ; sens inconnu (débit 1/2 Mbit/s ?). |
| 4 | RXSIZE | **R-C** | **décrémenté** à chaque mot reçu ; ne bloque jamais la réception. Final Lap le remet à 0 et exige −0x14 (−0x16) à l'IRQ ; le test en bouclage le charge à n et attend 0. |
| 5 | TXSIZE | **S-C** | nombre de mots à émettre. L'émission part quand TXSIZE ≠ 0 et START bit 0 = 0 ; TXSIZE reste ≠ 0 pendant l'émission (les jeux le testent comme « occupé ») et **revient à 0** à la fin. |
| 6 | RXOFFSET | **R-AD** | prochaine adresse de réception : les mots vont en `0x1000 | (RXOFFSET & 0xFFF)`, post-incrémenté sans toucher au bit 12. |
| 7 | TXOFFSET | **S-AD** | adresse de mot sur **13 bits**, post-incrémentée, qui reboucle dans sa moitié de RAM. Les jeux la réécrivent avant chaque trame ; 0x1000 + position sert à **relayer** une trame directement depuis l'anneau de réception. |

### 3.3 Ce que la puce ne fait pas
- **Aucun relais, aucun filtrage, aucune modification de trame, aucun ID d'anneau.** Tous les jeux relaient eux-mêmes.
  Ils incrémentent un compteur de sauts dans la trame en RAM RX, corrigent la somme et réémettent avec TXOFFSET = 0x1000 + position.
  Chaque jeu reconnaît et retire ses propres trames revenues (n° de PCB, emplacement, CPU NO.).
  Le nombre de bornes se déduit des sauts de sa propre trame quand elle revient : « UP TO n », « LINK OK n », LINKCT.
- Pas d'unité « octet » pour TXOFFSET : le `>> 1` de l'ancienne émulation (START = 3) est faux.
- Pas de recherche du bit de synchro en émission (`find_sync_bit`) ni de « += 0x100 » de TXOFFSET : ces mécanismes compensaient
  seulement l'absence de l'IRQ « émetteur libre ».

### 3.4 Interruptions
- Réception d'une trame → STATUS bit 1 → IRQ si MSK bit 3 = 1 et MSK bit 1 = 0 ; la puce met alors MSK bit 1 à 1.
- Émetteur libre (STATUS bit 2) et MSK bit 2 = 0 → IRQ ; la puce met MSK bit 2 à 1. Les jeux demandent ainsi une IRQ quand ils ont
  des trames en file (`MSK &= 0x0B` / `MSK = 9` au VBLANK) et vident la file une trame par IRQ ; ils laissent le bit à 1 (0x0D) quand la file est vide.
  Sans ce verrou posé par la puce, Cyber Commando, Armadillo Racing et Dirt Fox partent en tempête d'IRQ ou n'émettent jamais.
- **Une seule trame par IRQ de réception.** Les gestionnaires n'analysent que la dernière trame avant RXOFFSET. La trame suivante
  n'est écrite qu'une fois STATUS bit 1 effacé et MSK bit 1 remis à 0 par le jeu : c'est la dernière écriture de tous les gestionnaires,
  et Four Trax écrit STATUS = 0 avant l'acquittement du contrôleur d'IRQ.
- Les IRQ sont réévaluées à chaque écriture de MSK.

## 4. Le modèle d'émulation (`src/mame/namco/namco_c139.cpp`)
- Registres et RAM comme au § 3. L'émission recopie les mots au moment du départ ; l'émetteur reste occupé 5,5 µs par mot
  (environ 2 Mbit/s), puis TXSIZE revient à 0, l'émetteur redevient libre et les IRQ sont réévaluées.
- Réception : une trame réseau par cycle d'IRQ, écrite dans l'anneau RX, RXOFFSET avancé, RXSIZE diminué, STATUS bit 1.
- Transport : TCP, une connexion entrante (`-comm_localhost/-comm_localport`) et une sortante vers la borne suivante
  (`-comm_remotehost/-comm_remoteport`). Chaque trame est préfixée de sa longueur, avec les mots de 9 bits sur 2 octets.
  Une instance seule avec les options par défaut (port local = port distant) se connecte à elle-même : son anneau est bouclé,
  comme une borne avec un bouchon de test.
- Driver's Eyes : les trois C139 sont reliés directement dans le pilote (`add_local_peer`) ; ce que l'un émet arrive aux deux autres.
  Cela remplace l'ancien `sci_de_hack`, qui ouvrait des ports TCP fixes.
- Super 22 (`namcos22.cpp`) : une requête SCI levée pendant que le jeu a désactivé ce niveau au contrôleur système est mémorisée et
  délivrée quand il le réactive. Alpine Racer 2 coupe `$700002` pendant qu'il émet.
- Corrigé au passage : une course entre le thread de l'émulation et le thread réseau pouvait bloquer définitivement l'émission TCP
  (données restées dans la file sans envoi en cours).

## 5. Points encore hypothétiques
- Sens de START = 3 / 0x11 / 0 sous MSK 0x0F (débit ?), de CONTROL = 2 et des bits 0 et 3 de MSK (on exige seulement bit 3 = 1 pour les IRQ).
- Arrêt d'une émission au premier mot portant le bit 8 quand MSK bit 0 = 1 : FT (TXSIZE 0x2C pour 0x25 mots), DF (0x3F pour 0x20)
  et Winning Run (0x3F pour 0x2A) le suggèrent. Le modèle envoie tout TXSIZE ; les jeux le tolèrent.
- Câblage réel de Driver's Eyes et de Ridge Racer Full Scale (diffusion de la carte centrale vers les côtés).
- Débit réel de la ligne.

## 6. Résultats des essais (2026-11-03)
`c139.exe` contient les pilotes namcos2/21/21_c67/21_de/22 avec ce modèle. Les instances sont reliées par un anneau TCP local
qui reprend les adresses des bornes (127.0.0.4:15112 → 127.0.0.5:15113 → …). Chaque borne démarre sur sa NVRAM (§ 7).
Non-régression finale : les 15 jeux à 4 bornes, puis 6 jeux de familles différentes à 2 bornes avec la seconde lancée 12 s après.

Ce que chaque correction a réglé :
- La suppression du relais et de l'ID d'anneau, plus le verrou MSK posé par la puce, ont fait lier ridgera2, raverace, ainsi que Final Lap et les jeux
  à emplacements (Four Trax, Suzuka, Dirt Fox) quand chaque borne a son propre n°. L'ancienne émulation ne liait raverace qu'avec deux ID d'anneau identiques,
  et acedrive, victlap ou Winning Run qu'avec des ID différents, et seulement à 2.
- La correction de la course du thread réseau : sans elle, l'émission TCP d'une instance pouvait se bloquer définitivement (ridgera2 la provoquait).
- La relance d'une requête de réception restée sans réponse : Driver's Eyes au démarrage, Alpine Racer 2 pendant son émission.

## 7. NVRAM de link
Les NVRAM des bornes 1 à 4 de chaque jeu sont dans le dossier de résultats (voir le README qui les accompagne). Points particuliers :
- Final Lap 1/2/3 : n° de PCB 0xFE01 à 0xFE04 (octets 0x10-0x11), sans somme de contrôle.
- Armadillo Racing : l'enregistrement de réglages (0x200 octets) est vu par le 68020 en lignes de 16 octets à `r×16` et `0x1000 + r×16`.
  La somme 16 bits des octets 0-0x1FD est à 0x1FE (fichier 0x10FE-0x10FF). Il y a une copie de secours (lignes 0x10-0x1F).
- Winning Run GP / '91 : octets 8 (CAR TYPE) et 9 (CPU NO.), somme des octets 0-0xB en 0xC.
- Dirt Fox : CAR TYPE à l'octet 0x47, somme en 0x41 (fichiers générés par le menu).
- Alpine Racer 2 : octet 0x32 = 0 (LEFT) / 1 (RIGHT), sans somme.
- Cyber Cycles : octet 0x26 = ID (0-3), accepté tel quel (« ID NUMBER 2, LINK ON 2 »).
